NiYien TestFlight — 构建与上传步骤（2026-10-11）

目标：先发布小范围 TestFlight，按测试反馈再修功能。保留当前并发、
队列生命周期、导出流程和界面设计，不把额外功能改造当作首版前置条件。

GitHub Actions 自动编译上传：先提交并推送工作流与相关脚本到默认分支，
在仓库 Settings → Secrets and variables → Actions 中配置：
  默认复用已有 Secrets：MACOS_CERTIFICATES、MACOS_CERTIFICATE_PWD、
  MACOS_ACCOUNT_USER、MACOS_ACCOUNT_PASS。共享账号需有该 App 的上传权限。
  默认只新增 Secret IOS_PROVISIONING_PROFILE：com.niyien.stabilizer 的
  App Store .mobileprovision 描述文件，Base64 编码。Mac 上可执行
  base64 -i NiYien_dist.mobileprovision | pbcopy，再粘贴到 GitHub Secret。
  共享 P12 必须包含 Apple Distribution 证书及私钥；仅有 Developer ID 时，
  可将 iOS 分发证书一起导出到原 P12，或增加 IOS_CERTIFICATES 作为覆盖。
  覆盖的 P12 密码默认仍用 MACOS_CERTIFICATE_PWD，密码不同才加 IOS_CERTIFICATE_PWD。
  签名指纹会从已导入的 iOS 分发私钥自动匹配，通常不需增加变量。
  如果已有完整 MACOS_ITCONNECT_ISSUER / MACOS_ITCONNECT_KEY_ID /
  MACOS_ITCONNECT_KEY，会复用它们自动下载描述文件，无需 IOS_PROVISIONING_PROFILE。
  同样兼容 APPSTORE_ISSUER_ID、APPSTORE_API_KEY_ID、APPSTORE_API_PRIVATE_KEY。
  MACOS_ACCOUNT_USER/PASS 不可用时，完整 API 凭据可作为上传替代通道。
在 Apple Developer 中准备匹配分发证书和包名的 App Store 描述文件，
并在 App Store Connect 创建对应 App 记录；使用 API 时其权限为 App Manager。
随后在 Actions → iOS release → Run workflow 中选择最新源码分支运行；
直接运行时 upload_to_connect 默认关闭，只编译；需要上传时勾选该输入。
发布中心的“①触发构建 / ②创建并推送 Tag”也有同名上传勾选项，默认关闭。
未勾选时生成 unsigned 编译产物，不要求上述签名/上传凭据；勾选后才生成
签名 IPA 并上传。发布中心勾选后创建的 Tag 会记录这次选择，只构建一次。
普通 release tag 也会触发编译，默认不上传；IPA、调试符号和 receipt
保存在 niyien-ios artifact。
发布中心前后端、iOS 工作流和配套脚本需一起提交推送；更新后重启发布中心。
它替代本机打包与 Transporter 上传；上传后的测试组、外测审核及正式
App Store 送审仍在 App Store Connect 操作。下列步骤保留作本机验证与备用。

1. 同步源码
   在 Mac 的 gyroflow 仓库切到 niyien，git pull --ff-only origin niyien。
   Windows 的 .cargo/config.toml 存在未提交的 ../qml-video-rs 本地覆盖；
   不要复制它到 Mac。使用远端提交中的 Cargo.toml、Cargo.lock 和配置。
   官网是 NiYien/docs 的 main 分支，移动页面在 mobile/。

2. 工具链与签名
   使用正式版 Xcode 26 或更新版本及 iOS 26 或更新 SDK。
   先检查 xcodebuild -version、xcrun --sdk iphoneos --show-sdk-version。
   必要时切换 xcode-select 到完整 Xcode.app，而非 CommandLineTools。
   最低系统版本保持 iOS 15.0；不需改到 iOS 26。
   运行 just ios install-deps。检查 Qt iOS、OpenCV、FFmpeg 和 MDK 构建依赖。
   用户于 2026-10-07 确认现有 MDK Key 已获取授权，沿用当前 Key，
   无需重新申请。Qt/FFmpeg 及所修改 Qt 库的对应源码交付仍需核实。
   配置 SIGN_KEY 为 Apple Distribution 证书 SHA-1，PROVISIONING_PROFILE
   为明确授权 com.niyien.stabilizer 的 App Store 分发描述文件绝对路径。
   签名资料保留在本机或环境变量中，不提交证书、描述文件、密码或 API key。

3. 构建
   发布版本从 _deployment/mobile-version.json 读取，安卓和 iOS 共用；
   用 python3 _scripts/mobile_version.py 查看当前版本，App Store Connect
   的版本填写同一个值。下一版用 --bump patch，跳号可用 --set 1.0.5。
   just ios build-ipa 在编译前自动分配新的 build number，并在打包时沿用。
   自动计数保存在 target/ios-version/build-number.json。换电脑或清理 target
   后先核对 App Store Connect 已上传的号码；必要时设置
   NIYIEN_IOS_BUILD_NUMBER 为更大的构建号，此次构建后自动计数从该号码继续。
   CI 使用“下限首段 + workflow run number . run attempt”，下限 4 时
   首次运行为 5.1，重跑为 5.2，下一次为 6.1；首次接入前也需复核已上传号码。
   运行 python3 -B -m unittest discover -s _scripts/tests -p test_ios_metadata.py。
   运行 _scripts/test_ios_video_picker_bridge.sh 做原生桥接检查。
   运行 just ios build-ipa。此命令生成 deploy/distribution 包，保留 dSYM。
   package_ios.py 会检查实际可执行文件的 SDK，避免用新 Info.plist
   包装旧 SDK 构建。遇到原生编译或上传错误时，只修发布必需的问题。
   记录 IPA 的 SHA-256、build-receipt.json、dSYM 及 App Store Connect 上传结果。

4. 最小真机验证
   用 development 描述文件运行 just ios run，或安装内部 TestFlight 构建。
   冷启动后进入“设置 → 应用 → 帮助与支持 → 体验内置示例”。
   预览原始／稳定后，返回列表，导出，打开完成任务并分享／存储到文件。
   再用 Photos 或 Files 导入一段实际兼容素材，确认选择器取消后能重开。
   Windows 通过的宿主检查不能标记为 iOS 真机通过。

5. 上传与外部 TestFlight
   用 Transporter 或当前苹果支持的上传工具上传 distribution IPA。
   使用 _deployment/ios/store/app-store-submission.json 填写测试说明、
   Beta App Review 信息、反馈邮箱与隐私资料。
   核验 https://www.niyien.com/mobile/privacy.html 和 /mobile/help.html
   返回有效页面；审核示例下载地址为 /mobile/NiYien-review-sample.zip。
   当前示例 ZIP 的 SHA-256 为
   1e44481938a863fb1641d4247934301688939e64431656c180124cf84fcd24f5。
   审核联系人姓名、电话须由发布者提供；不能虚构。填写加密问题时须核对
   实际原生 SDK 的加密范围，不仅依据 Info.plist 的 false。
   提交首个外部构建的 Beta App Review，通过后邀请少量目标用户。
   用户已经授权本轮 Windows 准备并 push；本交接本身不代表已上传或送审。

6. 后续 App Store
   完成真机截图、年龄分级、发行地区及适用的主体/备案信息。
   并发、后台返回、长批次、4K/HDR、空间不足等放进 TestFlight 测试清单。
   不宣称未验证的编码器、格式或 iOS 性能已经受支持。
